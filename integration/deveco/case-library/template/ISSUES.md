# 图书管理系统 — 问题跟踪

真实项目里，agent 拿到的往往不是"从零实现"，而是这些报上来的问题。修复时请先复现、再定位、再改、再验证。

| # | 类型 | 报告 |
|---|---|---|
| 1 | UI 缺陷 | 借阅记录页在**没有任何借阅**时是一片空白，没有提示，用户以为坏了 |
| 2 | 功能缺陷 | 用 ISBN 搜索时，输入带连字符的 `978-7-5366-9293-0` 搜不到，但书明明在库里 |
| 3 | 逻辑缺陷 | 一本书的**应还日当天**就被标成"逾期"了，用户投诉；当天应该还不算逾期 |
| 4 | 并发/一致性 | 同一本书**能被连续借出两次**（没归还就能再借），导致两个借书人都以为借到了 |
| 5 | 性能 | 书目有 1000+ 条时，搜索框每输入一个字符就卡一下，列表滚动也顿 |
| 6 | 数据一致性 | **删除一本已被借出的书**后，借阅记录里还留着它，点进去报错 |
| 7 | 健壮性 | 搜索框输入 `%`、`_`、`\` 这类字符时，要么搜不到要么报错 |
| 8 | UI 状态 | 借出成功后列表**不刷新**，要手动退出重进才看到状态变化 |

> 说明：这些是**报告**，不是规格。是否属实、根因在哪，需要你自己复现和定位。
