# TSK 真实场景净收益测试清单

口径：原始tok=⌈原文字符/4⌉ · 压缩tok=⌈压缩后/4⌉(含 TSK 包裹头) · 毛省=原始−压缩 · **净收益=毛省−回读成本**。
回读成本=模型为取回原文细节发 tsk search 时，返回片段占的上下文（未计 search 调用本身的输入 token，~几十 tok/次，相对返回片段可忽略）。
常规任务若压缩文本已含答案 → 回读 0 次。数据源：确定性合成 repo（30 commits + 300 文件树 + 60 用例测试），真实命令真实输出，可复现。

## 汇总与结论

- 8 个触发压缩的命令场景：原始 25119 tok → 压缩后，毛省 **23539 tok**（**+94%**）。
- 常规任务（表 A）：回读 0 次 / 回读 0 tok → **净省 23539 tok**。
- 深挖任务（表 B）：回读 8 次 / 回读 4497 tok → **净省 19042 tok**。

**TSK 效果如何解释：** 工具输出按命令语义压成短文本（原始 tok → 压缩 tok，毛省可达 80-97%）。
常规开发任务所需的文件名/计数/失败行/行号/合计都在压缩文本里 → **0 回读**，净收益≈毛收益；
深挖原文细节时 tsk search 按需取回精确片段，单次回读成本通常仅为原文的 1/4~1/500 → **净收益仍为正**。
小输出（git status/df 等天然短）放行不压，零固定开销。

**边界案例（诚实记录）：** `wc` 这类输出本身不大（~500 tok）时，毛省仅 ~85%，而深挖单文件行数的一次回读可达原文同量级 → 净收益为负。
结论：压缩收益随输出增大而显著；对小输出，模型的『重跑原命令』比回读更便宜——这是 1600B 阈值存在的意义，也提示深挖回读应优先重跑而非 search 大片段。
