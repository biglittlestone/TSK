## 新增高收益轮（23–31）实测结论

**新增 9 轮的收益（109,532 tok）比前 22 轮全部收益（88,558 tok）还多 24%，而会话 input 用量相当（23.30M vs 23.93M）**——同量 input，收益翻倍。整体 e2e 从 0.370% 抬到 0.419%。

| 段 | saved | 净 | input | e2e% | 单轮均值 saved |
|---|---|---|---|---|---|
| 1–22 | 88,558 | 86,608 | 23.93M | 0.370% | 4,025 |
| 23–31 | 109,532 | 104,507 | 23.30M | **0.470%** | **12,170** |
| 31 轮全量 | 198,090 | 191,115 | 47.23M | 0.419% | 6,390 |

- **轮 31（git 全史考古）47,142 tok 破全场纪录**（原纪录轮 18 审查 26,452），26 次压缩，回读 48 次（3,600 tok）仍净 43,542——「历史越深、diff 越大」的排序设计兑现，git 类提款机在 31 轮历史之上收益翻番。
- **轮 25（前端抽组件）23,157 tok、21 次压缩**：跨文件 diff + 反复 hvigor 构建双重命中。
- 27 轮揭示上限规律：模型不会整 dump 294KB books.json（那会触发 ~73k 的 cat 压缩），而是写 node 脚本分段处理、只打印统计与样本（每次 19–20KB→~4.5k saved）。**大文件杠杆只在任务真需要逐条读全量时才打满**；即便如此 10,418 仍 24× 地板。
- 偏弱轮：26（shared 层，3,991，e2e 0.048%——input 异常大 8.32M 且几乎无大输出）、29（grep 审计，2,280）、23/28（3,123）——都超 437 地板但非巨星，说明"共享类型抽取"类任务压缩触发少。
- 实测 `node -e` 等命令的输出**也会被压缩**（27 轮两处各 ~4.5k），比"仅识别命令名才压缩"的文档结论更激进。
