# DevEco 10 场景基准设计（打 tsk 收益）

> 目标：10 个真实 deveco 开发任务，每个自然推进 ≥30 轮**有含义、非随机**的对话，
> 路径刻意反复触发**大工具输出**，命中 tsk 三支柱：**输出压缩(tsk compress) → KB/BM25 回读(search) → B 分节地图**。
>
> 术语（请对齐）：每个「场景」= 一个带目标的 deveco 任务；其一条会话 = ≥30 个**有意义**的 agent轮
> （每轮是上一轮的自然续进，非随机工具调用）。设计与 Measure 协议见文末。

## 收益命中地图（10 场景共同打点）
| tsk 能力 | 触发的大输出 | 命中场景 |
|---|---|---|
| `tsk compress` 逐命令压缩 | build/log/git log·diff/grep/ls/find/test 大输出 | 全部 |
| KB 落盘 + `tsk search`(BM25) 无损回读 | 被压缩原文 | 4,5,8,9,10 |
| B 分节地图（大输出→§章节+按节精取） | 长日志/海量测试输出 | 4,8,9,10 |
| `tsk analyze/exec` 沙箱（计算不入上下文） | 大文件汇总 | 3,5,8 |

## 场景一 ~ 十（每场景 ≥30 有含义轮）

### S1 HarmonyOS 模块实现 + 反复编译排错
- 目标：用 ArkTS 实现"笔记应用"核心模块并通过 `hvigor build`。
- ≥30 轮推进：读 spec→搭工程→实现 5 个页面/服务→**逐次 hvigor build**(每次编译错多行→tsk compress 蒸馏 ERROR)→修 5~8 轮→hdc 查看/试跑→git add/commit 多次。
- 非随机：按"一页实现→一编译→一修"的固定节奏推进，每轮只做下一步。
- 收益：`hvigor build` 大输出反复压缩(错误行保留)；git status/log 压缩。

### S2 多文件代码重构 + git 考古操作
- 目标：重构一个 6 文件模块到目标架构，用 git 保留可回滚节点。
- ≥30 轮：读现状→用 `git diff/log/status/show` 多次探历史(大输出压缩)→拆分/挪方法→每步 git add+commit(状态压缩)→`git diff` 核对→重构后全量测试。
- 非随机：严格"先查当前 diff → 改一处 → 提交一处"顺序。
- 收益：`git log --stat`/`git diff` 大输出;MB/BM25 回看历史节点。

### S3 工程脚手架 + 依赖/构建 + think-in-code 汇总
- 目标：从 0 搭一个 multilingual 工程，装依赖、构建、产饮水说明。
- ≥30 轮：脚手架→`npm/hvigor install`(大输出)→`build`(大输出)→**用 tsk analyze/exec 聚合包体/依赖树**→写 docs→再构建。
- 收益：装/构建大输出;tsk analyze 沙箱汇总(包体、依赖多大不入上下文)。

### S4 大日志/测试失败排查（B 分节主场景）
- 目标：修一个在超长测试+构建日志里失败的功能。
- ≥30 轮：`cat`/`tee` 大日志(tsk compress + **B 分节地图**)→定位段→`tsk search "关键字"` 精取原文→修→重跑(再大输出)→对比→修完。
- 收益：这是 **B(§章节地图)+BM25 精取** 的极端场景;原文一直可检索回读。

### S5 知识库构建（沙箱 + 检索）
- 目标：研读 N 个源码/文档，产出一份结构化设计说明。
- ≥30 轮：**tsk analyze/exec** 逐个文件聚合(行数/符号/依赖,只回结果)→归纳→`tsk search` 点查精确 API→写章节→复查。
- 收益：沙箱计算不入上下文 + BM25 回读精确 chunk;强打 A+支撑。

### S6 UI 迭代 + 反复构建/截图
- 目标：做一个多页 UI,经多轮构建+检查打磨到位。
- ≥30 轮：布局→样式→每轮构建(大输出)+自查→改 5~8 轮→多状态→收尾。
- 收益：每次 build 大输出压缩;ls/tree 看产物结构压缩。

### S7 git 仓库考古（bisect/log 大海捞针）
- 目标：在 200+ commit 的仓库定位一个功能何时回归。
- ≥30 轮：`git log --oneline`(大)→`git log --stat/show` 逐个版本看 diff(大输出压缩)→`git bisect`→`git diff` 找改动→结论。
- 收益：git log/diff/show 海量大输出反复压缩;KB 可回看历史。

### S8 性能/内存问题定位（流式大输出）
- 目标：定位一个内存/性能瓶颈。
- ≥30 轮：压测跑负载(大输出流)→`tsk analyze` 聚合指标→`tsk search` 找热点→改→复测→收敛。
- 收益：反复大输出 + 沙箱聚合 + B 分节长报告;A 的整文件分析场景。

### S9 全量测试驱动开发（红-绿-重构）
- 目标：对一个含 N 用例的模块做 TDD。
- ≥30 轮：写 1-2 用例→跑测试(大输出,tsk compress 保留失败)→实现→重跑(通过/剩余失败)→迭代 N 个用例→全绿。
- 收益：每次 vitest/jest 输出压缩(失败上限);KB 存历史测试输出可回看。

### S10 多模块并行构建 + 集成 + 排错（B 分节）
- 目标：构建+集成 3 个相互依赖的模块。
- ≥30 轮：并行构建(聚合大日志、**B 分节**)→集成测试(大输出)→`tsk search` 定位各模块失败→逐模块修→复构建。
- 收益：并行构建聚合日志的最大化分节 + 按模块精取;套娃守卫保证读 KB 直通。

## 非随机性保证（对每个场景）
- 每个场景给定**阶段化推进计划**（spec→实现→构建→测试→修复→提交 → 下一步），每轮只允许"读现状 → 做一步 → 验证"，杜绝随机跳工具。
- 每轮"有含义"= 必须推进一个明确子目标（新增/修改/构建/验证/提交），且引用上一轮结果。
- 30 轮下限由"≥3 个功能 × ≥5 个构建-修循环 + git 提交 × N"天然满足。

## Measure 协议（对拍）
- 每个场景 on(tsk 插件 + `tsk compress`+KB) vs off(插件移除) 各跑一条 ≥30 轮会话。
- 指标：会话真实 input token(deveco json 每步 tokens)、`tsk report` 输出压缩 saved、`tsk search` 无损回读命中次数、构建/测试失败最终是否修复(正确性)。
- 判定：on 的 total input < off 且 正确性=off 持平 ⇒ tsk 真省不破。
