## E. TSK 价值证据链（手动场 + 脚本场汇总）

### E1. 压缩证据（journal sandbox-output 内部口径）
- **手动场 ON**（最完整）：3 次压缩省 **6146 tok**
  - `cat full.log | tee` (20KB 大日志整读) 5101→5011 tok **省 98%** ← 大文件整读的典型靶点
  - `grep -n "^ERROR" full.log` 633→574 tok 省 91%
  - `tsk search` 回读 905→561 tok 省 62%（回读本身也压缩）
- **脚本场 ON**（4 场合计 saved 1722 tok，均值 574/场）：`grep ERROR` 2530B→236B 91%

### E2. 回读开销（tokens 价值口径 = saved − 回读）
| 场 | ONsaved | KB回读 | 回读tok | 净收益 |
|---|---|---|---|---|
| 1-on | 574 | 2次 | 143 | **+431** |
| 2-on | 574 | 2次 | 1275 | **−701** ← 回读超 saved |
| 3-on | 574 | 0次 | 0 | **+574** |
| 4-on | 0 | 0次 | 0 | 0 |

**含义**：回读是真实的净额扣减项。模型主动读 `.tsk/kb` 原文/`tsk search` 的次数越多，净收益越小。2-on 读 KB 原文花了 1275 tok（> 压缩省的 574）→ 该场 TSK 净亏。**触发量 = 模型行为**：模型不读 KB，TSK 白省；模型读 KB，回读成本吃掉收益。

### E3. 大文件/big 输出靶点（OFF 基线可见）
- `full.log` 26.6KB 整读 = est 6651 tok（r1-off 出现 1 次）← read 大文件靶点
- OFF 场 bash 输出无 >4KB 单次（模型自用 tail/head 截断）→ **真实业务里 bash 大输出主要来自构建/测试/日志命令，S4 用例没能触发**

### E4. 结论
1. **deveco 会话里工具输出占模型所见大头**：OFF 基线 bash 41% + read 44% = **85%** 的工具输出字符，是 TSK 可压空间。
2. **TSK 价值成立的条件**：模型执行"整读大文件/大输出命令"（cat/tail 大日志、构建、全量测试）→ 触发 >1600B 阈值 → 80~98% 压缩 + 原文落 KB 无损可回。
3. **TSK 价值被侵蚀的条件**：① 模型用 `| tail/head` 自截断（输出 < 阈值，白省 0）；② 模型频繁回读 KB 原文（回读 tok > saved，净亏）。
4. **本批 5 对均值**：每步 token ON 18.4k vs OFF 25.3k（ON 省 27%）；但 ON 完成 2/5 vs OFF 4/5（GLM 高方差）。
